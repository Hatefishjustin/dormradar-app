# 06 - 开发路线图

- 版本：v1.0（2026-09-23）
- 状态：已确认
- 原则：**每个阶段都有可验收的交付物**；阶段按依赖排序，但阶段内任务可并行；不追进度，追"每阶段结束都是可用的"。

---

## 阶段总览

| 阶段 | 名称 | 交付物 | 依赖 |
|---|---|---|---|
| 0 | 验证与准备 | 实测报告 + 工程骨架 | 设备在手、官方 App |
| 1 | MVP：连得上、看得见 | 可连接、可看实时数据的 App | 阶段 0 |
| 2 | 完整配置能力 | P0 复刻完成（含工程模式/底噪） | 阶段 1 |
| 3 | 后台监控与通知 | 7×24 监控 + 通知 + 事件时间线 | 阶段 1（可与 2 部分并行） |
| 4 | 调试与部署工具 | 日志导出、部署向导、配置模板 | 阶段 2、3 |
| 5 | 打磨与扩展 | 统计、小组件、OTA 评估、多设备 | 阶段 4 |

## 阶段 0：验证与准备（不写业务代码）

**目标**：把设计文档里所有"待实机验证"变成"已确认"。

任务：
1. 下载官方资料到 `docs/reference/`（协议 PDF、说明书 PDF、安卓 Demo zip、HLKRadarTool App）；
2. 研读官方安卓 Demo 源码，确认 BLE 服务/特征 UUID、密码鉴权时序，回填 docs/02、docs/03；
3. 真机安装官方 App，逐项操作并截图，产出《官方 App 功能实测清单》（存入 docs/02 附录）；
4. 用官方 App / PC 上位机确认设备固件版本与能力（分辨率、底噪、工程帧字段）；
5. 创建 Android 工程骨架（仅空壳 + 依赖 + CI 能跑通 + 协议模块的单测示例）。

**验收**：docs/02 §6 待验证清单全部打勾或转为"确认不支持"；工程能编译出空白 APK。

## 阶段 1：MVP —— 连得上、看得见

**目标**：完成最小闭环：发现 → 连接 → 鉴权 → 实时状态。

任务：
1. `core/protocol`：帧编解码 + 黄金测试（官方示例字节流 + 随机切片重组）；
2. `core/ble`：BleClient（扫描、连接、操作队列、状态机、手动重连）；
3. `RadarConnection`：连接编排（鉴权 → 读固件/MAC/参数）；
4. UI：扫描列表页 + 设备主页（有人/无人大状态、运动/静止距离与能量、连接状态）；
5. `FakeRadarSource` + 开发者选项模拟数据开关。

**验收**：真机从扫描到看到实时距离跳动全流程顺畅；杀掉重开 App 能重连；协议单测全绿。

## 阶段 2：完整配置能力（P0 复刻达成）

**目标**：官方 App 能配的，我们全能配；简单功能浅层直达，专业设置深层收纳（PRD 4.0 两层信息架构）。

任务：
1. 参数配置页（详细层）：最远探测距离（运动/静止）、无人持续时间、距离分辨率（能力允许时）；
2. 灵敏度页（详细层）：9 距离门 × 运动/静止滑杆矩阵，批量设置（含"全部距离门"），实时回读校验；
3. **一键设置（简单层）**：内置 ≥3 套推荐参数包（标准/近距/远距穿门），一键下发 + 回读校验 + 成功提示；
4. **能量实时曲线（简单层·首页图表区）**：运动/静止能量随时间曲线，叠加当前灵敏度门限线；
5. 工程模式页：各门运动/静止能量实时柱状图（+光敏值/OUT 状态，固件支持时）；
6. 底噪检测流程（简单层·引导式，能力允许时）：清场提示 → 开始/进度 → 结果展示 → 按建议值一键应用；
7. 设备管理：重启、恢复出厂（二次确认）、蓝牙开关（含误关恢复引导）、修改蓝牙密码、固件/MAC 展示、**光敏辅助控制**（模式+阈值+OUT 电平）、串口波特率、门限值；
8. 自动重连（指数退避）+ 断线 UI 反馈。

**验收**：对照 PRD 4.1 十六项清单逐项打勾（OTA 在阶段 5）；配置写入后重读一致；官方 App 与本 App 交叉验证配置互通。

## 阶段 3：后台监控与通知（核心增量）

**目标**：手机揣兜里也能知道走廊有人。

任务：
1. `RadarMonitorService` 前台服务 + 常驻通知；
2. `NotificationEngine`：规则、节流合并、免打扰时段、三档监控模式；
3. Room：事件流水入库 + 事件时间线页（筛选/跳转）；
4. 连接事件通知：断开/重连成功/重连失败；
5. 国产 ROM 保活引导页 + WorkManager 兜底 + 开机恢复；
6. 通知渠道设置页（每渠道独立铃声/震动/静默）。

**验收**：主力机 24h 实测：通知到达、断连有告警、自动恢复有记录；通知节流符合配置上限。

## 阶段 4：调试与部署工具

**目标**：不拆设备也能完成现场调参与排障。

任务：
1. 日志系统：分级日志查看、原始帧十六进制记录、zip 导出分享；
2. 部署向导：安装位置建议 → 底噪采样 → 有人走动采样 → 自动建议参数 → 应用并存模板；
3. 配置模板：保存/应用/差异对比/回滚；
4. 连接质量页：RSSI 曲线、丢帧统计、重连历史；
5. 事件回看调参：事件详情展示当时能量快照。

**验收**：用部署向导完成一次真实门板部署调参，误报率相比默认参数显著下降（实测记录写进交接文档）。

## 阶段 5：打磨与扩展（按需排序）

候选（进入本阶段前重新排序）：
- **OTA 固件升级实现**（已定为必做，见 ADR-009：本地固件文件 + 0x00C0 + 分包传输，协议细节研读官方 Demo OTA 模块后回填 docs/03）
- 走廊人流统计（按小时/星期热力图）
- 桌面小组件 / 快捷磁贴
- 多设备管理 UI
- CSV 导出、Home Assistant 联动（Webhook）
- USB-OTG 串口直连（见 ADR-008）

## 风险与依赖登记

| 风险/依赖 | 影响 | 缓解 |
|---|---|---|
| 官方固件分发渠道不可得 | OTA 无法实现 | 阶段 5 评估，不行就放弃（不影响核心目标） |
| 设备固件不支持底噪/分辨率 | 对应功能降级 | 能力探测 + UI 隐藏 |
| 国产 ROM 杀后台超预期 | 监控断连 | 多层保活 + 断连必告警（至少"死要见尸"） |
| 门板衰减过大导致漏报 | 核心价值受损 | 阶段 0 先做穿门可行性实测，不行调整安装方案 |
