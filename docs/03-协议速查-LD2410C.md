# 03 - LD2410C 协议速查

- 版本：v1.0（2026-09-23）
- 权威依据：**《LD2410C 串口通信协议 V1.09》（2025-06-09，官方 PDF）** + 说明书 V1.09
- 用途：开发速查。与官方 PDF 冲突时以 PDF 为准；标注"待确认"的条目在阶段 0 核实 PDF 对应页码后修正。

---

## 0. 总原则

- 全部数据**小端**格式，表中数值均为十六进制；
- BLE 与串口**同一套协议**（蓝牙透传）；BLE 侧注意：连接后先过密码鉴权（命令 `0x00A8`），数据按 MTU 分包到达，必须流式重组；
- 配置类命令必须先「使能配置」，配置完成后「结束配置」：
  `使能配置(0x00FF) → 任意配置命令... → 结束配置(0x00FE)`，否则命令无效。

## 1. 帧格式

### 1.1 命令帧（手机 → 设备）

| 帧头 | 帧内数据长度 | 帧内数据 | 帧尾 |
|---|---|---|---|
| `FD FC FB FA` | 2 字节 | 命令字(2B) + 命令值(N B) | `04 03 02 01` |

### 1.2 ACK 帧（设备 → 手机）

| 帧头 | 帧内数据长度 | 帧内数据 | 帧尾 |
|---|---|---|---|
| `FD FC FB FA` | 2 字节 | (命令字 \| 0x0100)(2B) + 返回值(N B) | `04 03 02 01` |

返回值前 2 字节为 ACK 状态：`0`=成功，`1`=失败。

### 1.3 上报数据帧（设备 → 手机，雷达检测结果）

| 帧头 | 数据长度 | 帧内数据 | 帧尾 |
|---|---|---|---|
| `F4 F3 F2 F1` | 2 字节 | 见 §3 | `F8 F7 F6 F5` |

> 解析器按帧头区分两类帧：`FD FC FB FA` = 命令/ACK 域；`F4 F3 F2 F1` = 数据上报域。

## 2. 命令一览

| 命令字 | 名称 | 命令值 | 备注 |
|---|---|---|---|
| `0x00FF` | 使能配置 | `0x0001` | 一切配置命令的前置。ACK 返回协议版本(2B)+缓冲区大小(2B，0x0040) |
| `0x00FE` | 结束配置 | 无 | 恢复工作模式 |
| `0x0060` | 最大距离门与无人持续时间配置 | 三组「参数字(2B)+参数值(4B)」：运动门`0x0000`、静止门`0x0001`（范围 2~8）、无人时长`0x0002`（0~65535 秒） | 掉电不丢失 |
| `0x0061` | 读取参数 | 无 | 返回：状态+头0xAA+最大距离门N+配置运动门+配置静止门+N个运动灵敏度+N个静止灵敏度+无人时长(2B)。**真机已验证（2026-09-27）**：字段顺序如上，首字节 0xAA 后是最大门（硬件门数上限），紧跟运动门、静止门——勿混淆（曾因错位导致"回读不一致"假故障） |
| `0x0062` | 使能工程模式 | 无 | 开启后上报帧带各距离门能量（见 §3.2） |
| `0x0063` | 关闭工程模式 | 无 | |
| `0x0064` | 距离门灵敏度配置 | 三组：距离门字`0x0000`+门号(4B，`0xFFFF`=全部门)、运动灵敏度字`0x0001`+值(4B)、静止灵敏度字`0x0002`+值(4B) | 灵敏度 0~100；设为 100 等于屏蔽该门 |
| `0x00A0` | 读取固件版本 | 无 | 返回版本号信息 |
| `0x00A1` | 设置串口波特率 | 2 字节档位序号 `1~8`：1=9600、2=19200、3=38400、4=57600、5=115200、6=230400、7=256000、8=460800 | 仅影响串口，不影响 BLE；默认档位 7（256000）。重启生效（官方 Demo 确认） |
| `0x00A2` | 恢复出厂设置 | 无 | 见 §4 出厂默认值 |
| `0x00A3` | 重启模块 | 无 | BLE 会断开，App 需自动重连 |
| `0x00A4` | 蓝牙设置 | `0x0100`=开 / `0x0000`=关 | 关闭后恢复方法：2~3 秒内断电重上电 5 次 |
| `0x00A5` | 获取 MAC 地址 | `0x0001` | 返回 2B 状态 + 1B 类型(0x00) + 3B MAC（大端） |
| `0x00A8` | 校验密码（获取蓝牙权限） | 6 字节密码，默认 `HiLink` | **BLE 连接后必须最先发送**，通过后才开始透传雷达数据（官方 Demo 确认） |
| `0x00A9` | 设置控制密码 | 6 字节新密码 | 用于修改默认密码 |
| `0x00AA` | 设置距离分辨率 | `0x0001`=0.2m / `0x0000`=0.75m | 需固件支持；设置后距离门含义变化（官方 Demo 确认） |
| `0x00AB` | 查询距离分辨率 | 无 | 需固件支持 |
| `0x00AD` | 设置光敏/辅助控制配置 | state(1B)+value(1B)；value=光敏阈值 0~255（默认 0x80）；**state 语义已由官方 Demo 确认（2026-09-27）：`0x00`=关闭 / `0x01`=光感低于阈值触发 / `0x02`=光感高于阈值触发** | V1.09 §2.2.18；OUT 引脚可联动光敏输出 |
| `0x00AE` | 查询光敏/辅助控制配置 | 无 | V1.09 §2.2.19；返回 state(1B)+阈值(1B)，固件 ≥2.01.23021610 追加第 3 字节电频状态（`0x01`=高电平） |
| `0x000B` | 开始底噪检测（灵敏度自动配置） | 2 字节检测时长（秒）。2410C 官方 Demo 固定发 `0x003C`（60 秒）；清单文档建议 5~10 秒，启动后约 10 秒开始出数 | V1.09 §2.2.20；期间必须无人；完成后输出各门能量最大/最小/平均值 |
| `0x001B` | 查询底噪检测状态 | 无 | 返回 0=未进行 / 1=进行中 / 2=已完成。⚠️ 来源为复刻清单（协议 V1.07）；官方 2410C Demo **未使用**该命令（其通过上报帧目标状态 0x04/0x05/0x06 判断进度），实现时优先按上报帧状态、0x001B 做兜底轮询（待真机验证） |
| `0x00C0` | OTA 升级使能/关闭 | `0x0001`=使能 / `0x0000`=关闭 | 使能后进入 OTA 传输流程（分包传输协议细节研读官方 Demo OTA 模块后回填，见 ADR-009） |
| `0x00C4` | 设置门限值 | 上限(1B)+`00`+下限(1B)+`00` | 2410C 新固件「门限距离」功能。⚠️ 官方 Demo 的 0x00C5 返回解析按「无标准 2B 状态字」口径读数（上限在状态字位置、结果字节 `0x01`=成功）；本 App 解析器做了双布局容错（AckParsers.parseThreshold），真机验收后收敛 |
| `0x00C5` | 查询门限值 | 无 | 2410C 新固件 |

## 3. 上报数据帧结构

帧内数据 = 数据类型(1B) + 帧内数据头 `0xAA` + 数据体 + 帧内数据尾 `0x55 0x00`。

### 3.1 数据类型

| 值 | 含义 |
|---|---|
| `0x02` | 目标基本信息（默认上报） |
| `0x01` | 工程模式数据（0x0062 开启后上报，在基本信息后追加各距离门能量） |

### 3.2 目标基本信息数据体（按字节顺序）

| 字段 | 长度 | 说明 |
|---|---|---|
| 目标状态 | 1B | `0x00` 无目标 / `0x01` 运动目标 / `0x02` 静止目标 / `0x03` 运动+静止；底噪检测期间：`0x04` 检测进行中 / `0x05` 检测成功 / `0x06` 检测失败 |
| 运动目标距离 | 2B | 单位 cm |
| 运动目标能量 | 1B | 0~100 |
| 静止目标距离 | 2B | 单位 cm |
| 静止目标能量 | 1B | 0~100 |
| 检测距离 | 2B | 单位 cm |
| （工程模式追加）最大运动距离门 | 1B | |
| （工程模式追加）最大静止距离门 | 1B | |
| （工程模式追加）运动能量[0..8] | 9B | 每个距离门 0~100 |
| （工程模式追加）静止能量[0..8] | 9B | 同上 |
| （工程模式追加）光照值 / OUT 状态 | 各 1B | **是否存在依固件而定，按帧长度容错解析（待实机确认）** |

- 上报频率：有目标时约 1 次/秒（**待实测**；不同固件/模式可能更高）；
- 基本帧体长 13 字节（对应长度字段 0x0D 左右），工程模式帧体约 35 字节 —— **解析时不要写死长度，按"数据长度字段 + 尾标识 0x55 0x00"双校验**。

## 5. 实现注意（写给解析器作者）

1. **流式重组**：BLE 通知按 ≤20 字节切片到达，一帧可能跨多个通知，一个通知也可能含多帧 → 解析器维护字节缓冲，循环扫描帧头；
2. **粘包/半包**：只有同时满足「帧头匹配 + 长度合法 + 帧尾匹配」才出帧，否则丢弃并继续扫（防帧头字节出现在数据区造成误判，连续失败时逐字节后移）；
3. **配置会话**：所有配置命令封装在一个"配置会话"里：发 0x00FF → 执行 → 发 0x00FE；期间暂停对上报帧的状态推送也无妨（配置态下设备停止上报目标数据）；
4. **ACK 匹配**：ACK 的命令字 = 原命令字 | 0x0100，按此匹配请求与响应；命令需串行发送（等 ACK 再发下一条），超时按 1~2 秒；
5. **密码先行**：BLE 连接建立、发现服务、使能 Notify 后，第一件事发 `0x00A8`（校验密码）；验证通过前不会收到上报帧；
6. **固件差异容错**：字段有无（光照/OUT）、距离分辨率支持、底噪命令支持，全部做能力探测而非按版本号硬编码。
